## 怎么读这张表

| 现象 | 含义 |
|---|---|
| `ais.cap.` 标记串 **0 条** | 那份 exe 里**没有任何能力标记串** —— `ais.cap.` 这个前缀在整个仓库里都不存在（`git log -S "ais.cap."` 只有档 0 起的提交） |
| 标记串少于登记表 | **有模块被 LTO 当死代码剔除了**（阶段七轮 2 的整座文本塔就是这样没的） |
| 「前端已嵌入」为否 | 那份 exe **不含前端** —— 它指向本机开发服务器（`devUrl`），不是发行版 |
| 大小几乎不变但 SHA256 变了 | 正常：前端资源被 brotli 压缩后大小接近，但内容变了 |

> ⚠ **SHA256 不可复现**：`build.rs` 每次构建都烧进一个构建时刻（epoch 秒），
> 所以**重新构建必然得到不同的指纹** —— 这是有意的（用户要能认出「这是刚那一份」）。
> 指纹是**那一次构建**的记录，不是可复现哈希。
> 跨版本比较请用**标记串集合**（稳定）与**能力核对结果**，别用哈希相等与否。

## 探针报告

- `probe-t1.txt` —— 档 1 的完整探针输出（`scripts\verify-release-binary.ps1` 生成）。

## 复现一份指纹

```bash
npm run release:exe
powershell -ExecutionPolicy Bypass -File scripts\verify-release-binary.ps1 -Report artifacts\probe-<档>.txt
```
